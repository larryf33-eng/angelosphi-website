# Angelos C. Painting Inc. — new website

A static, dependency-free marketing site modelled on the structure of
genesispropainting.com, built from the content on angelosphi.com.

## Files

```
index.html        Home
about.html        About / mission / vision / core values
services.html     7 services, each with a detail block + anchor link
gallery.html      Portfolio grid + before/after pairs
areas.html        4 counties + all 59 towns
contact.html      Contact details, estimate form, Google map embed
assets/css/styles.css
assets/js/main.js
build.py          Regenerates the 5 inner pages from a shared header/footer
```

Open `index.html` in a browser — no build step, no server, no dependencies.

### Editing the shared header / footer

The five inner pages are generated by `build.py`. `index.html`'s **body** is
hand-maintained, but its **header is not** — the file carries
`<!-- HEADER:START -->` / `<!-- HEADER:END -->` markers and the build rewrites
whatever sits between them. So the nav can never drift across pages. Change
the shell in `build.py`, then:

```
python3 build.py
```

Never hand-edit `index.html` between those markers; the next build discards it.

## Nav dropdowns

`Services` and `Areas` are dropdown menus, matching genesispropainting.com.

- **Desktop (>900px):** open on hover *and* on keyboard focus — the CSS uses
  `:hover, :focus-within`, so tabbing through the nav opens them too. No JS is
  required for the desktop behaviour at all.
- **Mobile (≤900px):** the same markup becomes a tap-to-expand accordion inside
  the drawer. The caret is a real `<button>` with `aria-expanded`, so the
  top-level word ("Services") still navigates to the page while the caret
  expands the list — that's how Genesis behaves and it's what touch users
  expect. Opening one closes the other; `Escape` closes both.

The contents are **data-driven** in `build.py`; edit the list, re-run the
build, and the menu updates on all six pages:

| List | Feeds |
|---|---|
| `SERVICES` | The Services dropdown (also the service cards and detail blocks) |
| `COUNTIES` | The "Counties" column of the Areas dropdown |
| `FEATURED_TOWNS` | The two "Popular towns" columns of the Areas dropdown |

Every town on `areas.html` gets an `id` from `town_slug()`, so a town promoted
into `FEATURED_TOWNS` automatically has a working anchor. Sections carry
`scroll-margin-top` so a jumped-to anchor clears the sticky header instead of
hiding under it.

When per-town landing pages exist, point `FEATURED_TOWNS` at those URLs
instead of the `areas.html#town` anchors — that's the one change needed.

## Colour palette

Change these and the whole site re-skins:

| Token | Value | Use |
|---|---|---|
| `--navy` | `#12294A` | Headers, footer, dark bands |
| `--navy-800` | `#0d1f38` | Top bar, footer background |
| `--red` | `#C8102E` | Buttons, accents, eyebrows |
| `--ink` | `#1B2430` | Headings and body copy |
| `--surface` | `#F4F6F9` | Alternating section backgrounds |

**These are an approximation.** The live angelosphi.com colours could not be
read programmatically (it is a GoHighLevel site and the colour lives in
stylesheets that are not retrievable through the tools available). Sample the
real brand navy and red off the live site or the logo file and drop the exact
hex values in here.

## Before this goes live — open items

1. **Email address.** `info@angelosphi.com` is used throughout and is a
   **guess** — the real address on the current site was masked and could not be
   read. Confirm it and find/replace across all six pages.
2. **Contact form has no backend.** `assets/js/main.js` currently falls back to
   opening the visitor's mail client so nothing is silently lost. Point it at a
   real endpoint (the existing GoHighLevel form, Formspree, Netlify Forms, or
   the CRM this project ends up using) before launch.
3. **Social links are `#` placeholders.** The current site links to Facebook,
   Instagram, YouTube, X and Houzz; drop the real profile URLs into the footer.
4. **Testimonials are labelled placeholders.** Three cards on the home page are
   marked "ADD REAL REVIEW". Paste in real Google / Houzz / Facebook reviews.
   No invented reviews or ratings were used anywhere.
5. **Before/after pairs reuse existing portfolio photos.** Replace each pair
   with a genuine before and after of the same room or elevation — these are
   the highest-converting element on a painting website.
6. **Footer tagline** is `Quality work. Fair prices.` — a placeholder. Swap in
   Angelo's real tagline if he has one.
7. **Licence / insurance numbers.** Nothing was listed on the current site.
   If Angelo is licensed and insured, say so with the numbers — it is one of
   the strongest trust signals for a contractor and competitors show theirs.

## What is *not* claimed

The reference site leads with hard numbers (3,000+ projects, 250+ reviews,
3-year warranty). None of that exists for Angelos, so the stat band uses only
what the current site actually states:

- 25+ years of experience
- 4 counties served
- Available 24/7
- Free on-site estimates

Add real figures when they can be substantiated.

## SEO notes

- Unique `<title>` and meta description per page.
- `HomeAndConstructionBusiness` JSON-LD on the home page with NAP, hours and
  service areas. **Add the Google Business Profile URL to `sameAs`** once
  available — it is the single highest-value local SEO addition.
- `areas.html` lists all 59 towns, which is the page that will pick up
  "painter in <town> NY" long-tail searches. Individual town landing pages are
  the obvious next step if local search is a priority.
- No `sitemap.xml` or `robots.txt` yet — add both at deploy time.

## Hosting

Static files, so any host works: Netlify, Vercel, Cloudflare Pages, GitHub
Pages, or an S3 bucket. Drag the folder in and it runs.

## Accessibility / QA already done

- Verified no horizontal overflow at 320, 360, 390, 480, 720, 768, 900, 1024,
  1150, 1280, 1440 and 1920 px.
- Header stays on one line at every desktop width; the phone block drops out at
  1150px before it can collide with the nav.
- All internal links and anchor targets resolve, including every dropdown link.
- Dropdowns open on hover **and** keyboard focus; carets are real buttons with
  `aria-expanded`; `Escape` closes them; a resize across the breakpoint resets
  any that were pinned open.
- Anchor targets clear the sticky header (`scroll-margin-top`), and a town
  jumped to from the Areas menu is briefly highlighted so it's findable among
  the 59 rows.
- No JavaScript errors. The site renders and is fully navigable with JS off —
  including the dropdowns on desktop, which are pure CSS. Without JS the mobile
  drawer and the form handoff are the only things that don't work.
- `prefers-reduced-motion` respected.
